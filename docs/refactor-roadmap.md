## 阶段 1：先保证改得安全

工作包：

1. 固定兼容 Node/TypeScript/vue-tsc 版本组合与锁文件；拆分只检查、不自动修复的 lint 命令；Linux 构建可运行。
2. 先为匿名草稿、隐藏文章、分类更新 ID/slug 冲突、草稿管理列表编写失败测试，再修复行为。
3. 确立 Markdown 清洗策略及安全测试；覆盖管理 API 未认证、过期、伪造 token。
4. 建立独立测试数据库，不从开发默认环境自动加载生产凭据；生产迁移从应用启动剥离前先记录现有 schema。
5. 备份/恢复演练、PR 质量门禁；禁止测试连接生产库。

验收：权限三状态×四身份用例完整执行；非法 slug 更新不能改动其他分类；脚本和恶意 URL 不执行；所有新修复都有回归测试。测试工具链如需新库，先记录选型，本文件不冒充已有测试命令。

回退：独立修复 PR 可逐个回退，但不可重新上线已确认泄漏内容的版本；使用修复后的稳定版本作为后续回滚基点。

## 阶段 2：让阅读体验真正改变

先做首页、文章页两张高保真实现，评审后扩展列表、分类、关于、工具壳和后台布局。新增状态组件至少包含 loading/empty/error/retry；公开组件不依赖 Element Plus。

验收矩阵：首页、列表、文章 × 375/768/1440px × 中英 UI × 深浅主题，共 36 组固定截图；另在 320px 验证溢出，在长标题、长代码、表格、图片失效、无封面和 API 错误下补边界截图。

量化与人工门槛：

- 正文普通文字对比度 ≥4.5:1，大文字与关键非文本交互 ≥3:1；键盘可完成导航、搜索、目录和主题切换；焦点可见，无键盘陷阱。
- 全页横向溢出 0（代码/表格局部滚动允许）；可见页面唯一主 h1；图片不发生未预留尺寸导致的大幅跳动。
- 用户与实施者分别按品牌识别、层级、阅读舒适、双主题一致性、移动可用性五项 1–5 分评分，平均 ≥4 且每项 ≥3。用户未评审则标“待确认”，不由实施者代签。
- 核心流程无回归：查文章、搜索筛选、打开详情、登录、编辑保存、上传、公开/隐藏、分类编辑、AI 流式、工具入口。

回退：保持 API 不变，旧布局/页面在迁移发布期间可切回；视觉修改不得伴随破坏性 schema 变更。

## 阶段 3：证明后续开发更方便

按设计迁移 content，再迁移 identity/media/ai/settings/tools；入口通过兼容转接，保持旧 URL 与响应契约。数据库变更使用显式版本号和校验，空库及旧库副本都能升级。

验收：

- shared → module 反向依赖、模块内部越界导入、领域层导入 Gin/GORM 均为 0，由自动检查执行而非口头约定。
- 已迁移核心业务用例 Go 语句覆盖率 ≥80%；前端新增纯逻辑与状态转换覆盖率目标 ≥80%，需选定测试工具后生成报告。排除生成文件，不排除复杂业务来提升数字。
- 核心 E2E 全通过，包括未保存退出、上传失败、草稿恢复可见、分类重命名和公开→隐藏后的匿名访问。
- 在测试分支演练增加一个最小“阅读清单”模块，只新增模块、路由注册、导航配置与必要契约/迁移；无关业务模块实现改动为 0。不把演练功能强行加入生产。
- 数据对账：文章 ID/slug/正文哈希/发布可见性、分类标签关联、上传文件数量和哈希 100% 一致；现有 URL 清单无意外 404。

回退：新旧应用兼容扩展后的 schema；不执行删表/删列回滚。必须破坏性变更的任务移到独立版本，不混入模块迁移。

## 阶段 4：SSR 与性能准入

PoC 首选 Nuxt，但只有证据证明 Vue 复用、编辑器隔离、私有态隔离和部署资源可接受后才采纳。ADR 需记录精确版本、依赖新增、Node 内存/CPU 峰值、构建时间、运维成本和回退方案。PoC 不通过则停在阶段三，SSR 目标明确未达成。

固定测试条件：生产构建、固定 Chrome/Lighthouse 版本与移动模拟配置、同一预发布机器、匿名冷缓存、同一数据集（至少 100 篇，包含长文/代码/图片）、每页 3 次取中位数；保存原始报告而非只记录分数。第三方 AI 不进入公开阅读性能测试。

| 指标 | 发布目标 | 测量方式 |
| --- | --- | --- |
| Lighthouse Performance | 首页/列表/代表文章均 ≥90 | 固定配置，3 次中位数 |
| 实验室 LCP / CLS | ≤2.5s / ≤0.1 | 同上 |
| 首屏 JS | 每个公开代表页实际请求累计 gzip ≤200KiB，不含未加载后台 chunk | 浏览器网络 + 构建分析，记录压缩方式 |
| 公开 API | 10 并发、持续 60s、预热后 p95 ≤300ms，错误率 <1% | 固定数据、同机房，记录机器配置；计时不包含浏览器渲染 |
| 语义与 SEO | 原始 HTML 含标题正文/meta；不存在内容返回 404；旧链接单次永久跳转到 canonical | HTTP 请求、禁 JS 浏览器、站点链接爬取 |
| 隐私 | 草稿/隐藏不出现在 HTML、payload、搜索、sitemap、RSS 或缓存中 | 两身份并发请求、公开后隐藏再请求、无凭证抓取 |

上线后有足够真实样本再按 28 天窗口 p75 验证 LCP ≤2.5s、INP ≤200ms、CLS ≤0.1；低流量无法得出结论时标记样本不足。Lighthouse 分数不能替代真实 INP。

回退：Nginx 切回阶段三前端和安全修复后的 Go 版本，保留兼容 API/数据；关闭新增缓存。SSR 性能不达标不得简单提高预算掩盖问题，修改预算须有测量依据及设计变更记录。

## 阶段 5：发布不是最后一次构建

先预发布观察 24h，再按明确的维护窗口切流；没有蓝绿实例与流量切换验证，不称为零停机。健康检查、文章读取、登录编辑、图片、AI SSE、工具路径都需冒烟。

目标：固定 SHA 可回滚 ≤10min；在隔离环境恢复数据库与上传文件 ≤60min；日常备份恢复点目标 ≤24h，正式迁移切流前暂停写入并取一致备份，以实现该迁移窗口数据丢失 0。备份存放异机并加密、限制权限。

记录恢复后行数/哈希和权限验证，演练失败阻断上线。站点故障回滚应用优先；只有确认数据库损坏并评估新写入损失后才执行恢复，禁止无条件覆盖生产库。

交接文档更新真实架构、API、启动/测试命令、迁移命令、模块新增指南、依赖升级策略和告警处置。旧文档删除误导性“已完成”表述或清晰标为历史。
